# Universe3D Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A WPF/C# desktop app that shows galaxies, galaxy clusters and quasars in 3D, centered on the Sun. It shows
one selectable data set at a time, with redshift/blueshift, velocity, type and shape, optional velocity arrows,
and zoom, rotate and maximum-distance controls.

**Architecture:**
- `Universe3D.Core`, no UI: physics, coordinates, morphology, shapes, catalog pipeline and snapshots. It is fully
  unit-tested.
- `Universe3D.Rendering`: OpenTK/OpenGL renderers and the camera, inside a GLWpfControl.
- `Universe3D.App`: WPF MVVM shell.
- One set of builders produces both the built-in snapshots (through a console tool) and the in-app
  "Download latest" result.

**Tech Stack:**
- .NET 8 (`net8.0`, `net8.0-windows`), WPF and CommunityToolkit.Mvvm 8.3.2
- OpenTK 4.9.4 and OpenTK.GLWpfControl 4.3.6, OpenGL 4.1 core
- xUnit

**Spec:** `docs/superpowers/specs/2026-11-10-universe3d-design.md` (read it alongside this plan).

## Global Constraints

- Platform: Windows 10 22H2+ / 11, 64-bit; **OpenGL 4.1 core minimum**; .NET 8 Desktop Runtime.
- Cosmology: flat ΛCDM, **H₀ = 70 km/s/Mpc, Ωm = 0.3, ΩΛ = 0.7**, c = 299,792.458 km/s. z → D_C table over 0 ≤ z ≤ 8.
- CMB dipole: **369.8 km/s toward l = 264.0°, b = 48.3°**. Local Group frame: `v_LG = v_hel + 300·sin(l)·cos(b)`.
- Galactic frame (IAU): north pole RA 192.85948°, Dec 27.12825°; l of the north celestial pole 122.93192°.
  Supergalactic: north pole at l = 47.37°, b = 6.32°; SGL = 0 at l = 137.37°, b = 0°.
- Milky Way: center **8.2 kpc** from the Sun toward l = 0°, b = 0°; disk 30 kpc across, in the galactic plane.
- Disk intrinsic thickness **q₀ = 0.2**. Disk-normal sign convention: tilted toward +north (stated in the info panel).
- Cross-match tolerance **30″**. Quasar snapshot cap **250,000** by R (else B) magnitude.
- Reduced defaults on minimum-class GPUs: quasar limit **100,000**, galaxy-shape cap **5,000**. Recommended class:
  shape cap **20,000**.
- Camera distance **10⁻⁴ … 10⁵ Mpc**; wheel **15% per notch**; fly-to **0.8 s**; picking radius **8 px**.
- Velocity-arrow length `L = clamp(k·log10(1 + |v|/100), 3, 60)` px, default **k = 18**. Red = receding, blue = approaching. Arrow
  modes are labeled exactly **"Observed"** and **"Peculiar velocity"**.
- Shape LOD: a dot below 4 px, cross-fades to a shape between **4 and 8 px**. At most **60 labels** per frame.
- VizieR: `https://vizier.cfa.harvard.edu/viz-bin/asu-tsv` first, then `https://vizier.cds.unistra.fr/viz-bin/asu-tsv`.
- Cache folder: `%LOCALAPPDATA%\Universe3D`. Every astronomy term shown in the UI has a tooltip from `Glossary`.
- Every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Objects with no valid distance** (nearby galaxies with CMB-frame cz ≤ 0 and no measured distance): placed with
   the Local Group frame velocity if that is > 0, otherwise excluded and counted. They must never be drawn at the
   Sun or at NaN. *Test: Task 7, `DistanceResolver_ExcludesNonPositive`.*
2. **Catalog rows with blanks or junk** (empty cz, "----" type, NaN magnitudes, RA 360.0): skipped and counted, never
   thrown. *Test: Task 6, `TsvTable_ParsesBlanksAsNull` and Task 8, `Builder_CountsSkippedRows`.*
3. **Zooming deep into a far object** (a 2MRS galaxy at 200 Mpc, camera at 10⁻³ Mpc): no jitter; the camera relative
   precision holds. *Test: Task 10, `OrbitCamera_RelativeToEyeSplitKeepsPrecision`.*
4. **Switching data set or frame while a download runs**: the download finishes or is cancelled cleanly, and the view
   never shows a half-built data set. *Test: Task 14, `DownloadService_CancelLeavesSnapshotUnchanged`.*
5. **Search terms with spaces, case or leading zeros** ("m 31", "NGC0224", "3c273"): they resolve to the same
   object. *Test: Task 13, `Search_NormalizesNames`.*

### Task 6: VizieR client, TSV parsing and sky cross-matching

**Files:**
- Create: `src/Universe3D.Core/Catalogs/{IVizierClient,VizierClient,TsvTable,SkyCrossMatcher}.cs`
- Test: `VizierClientTests.cs`, `TsvTableTests.cs`, `SkyCrossMatcherTests.cs`

**Interfaces:**
- Produces:
  - `interface IVizierClient { Task<TsvTable> QueryAsync(string source, IReadOnlyList<string> columns, IReadOnlyDictionary<string,string>? constraints, CancellationToken ct); }`
  - `VizierClient(HttpClient http, IReadOnlyList<string>? mirrors = null)`. The mirrors default to Global Constraints
    order. It builds `?-source=…&-out=a,b,c&-out.max=unlimited&<constraints>`, tries each mirror in turn, and throws
    `VizierUnavailableException` (with all the reasons) when every mirror fails. The User-Agent is `Universe3D/1.0`.
  - `TsvTable.Parse(TextReader)`: it skips `#` lines, reads the header row, and skips the units and dashes rows.
    It provides `int Count`, `string? Get(int row, string col)`, `double? GetDouble(int row, string col)` and `int? GetInt(...)`.
    Blank or `-`-only cells are null.
  - `SkyCrossMatcher(double toleranceArcsec = 30)`: `void Add(double raDeg, double decDeg, int index)` and
    `int FindNearest(double raDeg, double decDeg)`, which returns −1 when nothing is within tolerance. It hashes on a
    Dec band × RA cell grid sized to the tolerance and checks neighbouring cells, including across RA 0/360 and near the poles.
